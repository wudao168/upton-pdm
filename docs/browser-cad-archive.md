# 网页存档入口

项目图档设计树（包括空项目）和标准结构图档列表底部共用“存档”入口，支持 SolidWorks 原生文件、文件夹和 ZIP。单次最多 2000 个文件，上传及解压总量不超过 2GB。选择根图档后，后台读取当前设计树及关联工程图；树外资料保留在暂存区，不自动登记或计入 BOM。

## 权限与开关

- `PdmSystemSettings.BrowserCadArchiveEnabled` 为总开关，默认启用。管理员在“系统设置 → 编号与存储 → 存档位置 → 网页存档入口”修改；关闭不影响插件存档。
- 项目入口要求现有图档编辑、项目存档、项目人员及文件夹权限。标准结构要求现有标准化部门存档授权，管理员身份本身不代替该授权。
- 接收文件、启动任务和正式提交均在服务端检查。任务绑定发起人和公司；后台执行时重新解析有效账号、公司访问范围和权限。浏览器隐藏按钮不作为授权依据。

## 数据与版本

- 原始上传内容保留在专用任务目录。后台仅在工作副本中绑定已提供或已核实的 PLM 引用，原文件不改写。工作副本使用短路径；不同原生文件同名时明确报冲突，避免串图。
- 每个任务号同时作为存档批次号和会话号；服务重启、丢失响应和同任务重试先核对回执。未变化文件复用原版本，子件变更不自动给父装配升版。
- 通过现有整批提交生成图档、关联关系和当前结构，复用现有 BOM 分类、人工覆盖、审核、发布和 U9 流程。存档不等于发布。
- 标准结构保留待分类 BOM 行，不静默丢弃；待分类明细补齐前不能作为完整 BOM 引用到项目。
- 新工作版本的 STEP/PDF 预览绑定其源文件校验值；不改写已发布版本的预览。预览异常不撤销已经成功的原生存档。

## 后台运行

API 的 `BrowserCadArchiveHostedService` 消费持久化任务。`UPLM-BrowserCadArchive` 隐藏计划任务运行独立的 `Upton.Pdm.CadArchiveWorker`，队列位于 `UploadTempRoot` 同级的 `browser-cad-archives`。当前配置为 `D:\PDM\Temp\browser-cad-archives`。

SolidWorks 后台解析需要 Windows 登录会话。生产解析账号应持续登录且工作进程在线；注销该账号会暂停解析，API 仍保留已接收文件，不能把仅上传成功误报为存档成功。工作进程使用独立 CAD 进程及隔离副本，不接管业务客户端的 SolidWorks。

状态依次为接收、待确认根图档、排队、解析、提交和成功/失败。失败保留上传文件；权限撤销、实际缺件或版本冲突会给出中文原因。历史导入路径和树外引用不单独构成存档门槛。
