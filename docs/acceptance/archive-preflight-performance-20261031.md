# 存档预检查耗时与超时修复

候选版本：2026.10.31.151000。最终本机部署状态记录在 `tmp/archive-preflight-performance-20261031/final-verification.json`。

## 本次复现

OP170.01.01总装在130000版选择332份文件，11:52进入，12:31结束。两份装配在12:12:26和12:13:54保存成功，随后又进行一轮完整引用检查。最终失败由客户端批量预检查的15分钟累计计时触发，未开始上传。

旧计时器只传给部分方法；加载、保存、重新核对使用另一个取消令牌，因此计时到期后仍继续读取，在后面的BuildBatchCheckInPlanAsync入口才抛出取消异常。

日志进一步定位到：壳体组件-HE450-A.SLDASM在11:58:00至12:02:44之间逐条生成128条引用提示，耗时约284秒；第二轮同处约263秒。旧引用补齐循环对每条待核对引用重新读取同一文档的整份ListExternalFileReferences状态。这部分没有包含在原有“读取已保存引用/建立嵌入索引”计时中。

## 修改

1. 按单个文件、单轮引用核对批量读取历史断开状态。128条引用共享一次原生状态读取，但逐条保持原判断和提示。
2. 同一路径有多个原生状态时，只有全部为已断开才确认；未加载、待保存、多配置、数量不一致等仍不能获得断开证明。不按缺失路径或文件名猜测。
3. 缓存仅在单文件当前核对轮次使用。保存后或新一轮核对重新读取，不跨保存复用原生特征状态。
4. 初次范围检查先完成结构、图档身份和权限核对，再保存已选且已打开的必要修改；保存完成后读取最终引用。若保存改变结构，仍重新读取结构，但不先浪费一轮即将失效的完整引用分析。
5. 后续预加载、发现新依赖或产生待保存状态时，原有保存与重新检查回退保留，不为提速跳过最终验证。
6. 删除混用的“整段预检查累计15分钟”取消源。保留会话/用户取消，统一传递；单次网络请求原有超时保持不变。原生同步调用不能安全强制中断，只在调用返回后的安全边界处理取消。
7. 新增每文件引用处理整体耗时、批量历史断开证据读取耗时、保存权限与保存耗时、完整范围核对耗时。记录包括非原生调用间的路径匹配和提示处理，避免长时间只显示一个笼统阶段。

独立存档窗口保持130000版；未改服务器、数据库、上传协议、引用/版本规则或管理员警告策略。未断链、改名、减少提示或静默扩大勾选范围。
