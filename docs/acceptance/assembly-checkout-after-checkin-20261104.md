# 子件及工程图成功存档后获取总装权限误拦截（2026-11-04）

## 证据及根因

本机 220000、进程 33460，22:33 至 22:34 成功提交“标签机钣金”零件和工程图，22:36 两次获取 `CW004-3.SLDASM` 权限均被零件的“尚未确认基准的本地修改”拦截。

只读查询确认：零件 W4（359cd3ec-d281-4f13-b856-b94ef5451171）、工程图 W5（4816a688-de5a-4524-9f1f-df44fa73d534）已提交。原工作文件保留旧磁盘绑定 W3/W4，两者当前指纹都匹配成功存档回执的源指纹。此机制保留原窗口和原文件，与上传的当前状态副本分别记录。

`TryAcquireReusableWorkingCopyAsync` 只认可磁盘基准和活动编辑草稿，没有采用已有的 `WorkingReuseCommittedMemoryMatches` 校验。因此，已确认提交的内存状态仍可能被当成未提交修改；随后工作区旧磁盘版本与服务器新版本的比较也会失败。新增完整 43 文件获取流程用例可在 220000 复现同一报错。

原真实会话在采样存档证明修订计数前已退出，未取得其运行中修订计数。因此不声称已证明现场当时每项内存条件或已完成真实总装获取验收；修复仅接受完整证明仍有效的情况。

## PDM 对照与范围

官方 [Reference Dialog 设置](https://help.solidworks.com/2025/english/EnterprisePDM/Admin/IDD_PAGE_LOCK_FILES.htm?id=2.27.16.17) 区分所选图档及引用的获取、检出；[Check Out Dialog Box](https://help.solidworks.com/2023/English/EnterprisePDM/fileexplorer/r_File_Check_Out_Dialog_Box.htm) 说明未勾选检出和获取的本地文件保持不变。UPLM 的内存副本提交和源文件单独保留是自定义机制，不表述为 PDM 原生内部行为。

此次仅补齐：请求总装权限时，已成功提交、仍能严格验证的未选子件可复用当前内存状态。真正未提交的修改继续保护，不自动获取子件或工程图权限、不强制保存原文件、不重开窗口、不创建服务器版本。

## 实现

- 仅修改 `PdmAddin.WorkingCopyReuse.cs`。
- 未选文件只有名称、物理路径、配置一致，并通过现有完整存档内存证明，才跳过错误的未提交判定。证明核对同账号/服务器公司、文档/版本、同一加载实例、修改事件计数、原生更新标记、源指纹及长度、提交副本指纹及长度。
- 版本比较使用临时投影，以已提交的内存版本参与比较；物理文件绑定和真实工作区清单保持旧磁盘基准，不冒写版本。
- 在首个检出请求前、服务器最新清单复核后分别重验，内容或身份变化时不解锁总装。
- 活动草稿冲突、所选子件的获取、其他未提交内容和既有图模权限关联规则保持原样。
