## 本次失败与根因

P700016-12批次 `9b17c7ba-26db-4a75-9b71-dade7793c782`：2026-10-30 23:48:37开始整批提交，23:50:35服务器在117364毫秒后返回400。数据库只读核对为847个Staged上传、0正式版本、0提交回执。

从当前19204进程只读提取3785个插件关系节点，不调用CAD文档接口、不读取凭据、不改写图纸。失败后的冻结对象已不在采集结果中，因此使用实际关系树与隔离占位文件重放生产 `CaptureArchiveSnapshot`，没有声称取到了原HTTP请求体。

根因：原生文件清单遍历会继续进入“配套工程图”，再跟随工程图的多模型关联进入父装配体/兄弟装配体。前面的CAD依赖检查正确跳过工程图消费者，而后面生成上传快照时把这些导航关系补成了3D普通文件依赖。旧插件重放恰好生成相同的两组循环：

- 70004158.F02.02.02、70004158.F02.02、70004158.F02。
- 70004158.Z02.03、70004158.Z02.04、70004158.Z02。

## 修复边界

1. 收集模型的原生依赖时，不再沿关联工程图继续遍历其他模型。工程图自身作为存档根时，依旧保留全部模型引用。
2. 第7步针对即将上传的固定快照，以图档ID检查整个选中批次的依赖。遍历、上下文/未知引用边界与服务器 `ArchiveBatchRules.Order` 对齐，使用同一份 `ReferenceCycleGroups` 环检测核心。
3. 校验在后台执行，不调用SolidWorks；在任何文件上传前结束。图档身份不一致、非法延后引用标记或真正循环均提前停止。
4. 第9步服务器校验继续保留，仍防止并发版本、权限等变化；不把既有问题晚发现解释成正常行为。

这符合PDM对[Contains](https://help.solidworks.com/2014/English/EnterprisePDM/FileExplorer/r_Contains_Tab.htm)和[Where Used](https://help.solidworks.com/2021/English/EnterprisePDM/FileExplorer/r_Where_Used_Tab.htm)的方向区分：可一起展示或提交配套工程图，不代表模型反向依赖工程图中的全部模型。具体快照遍历和前置校验是UPLM实现。
