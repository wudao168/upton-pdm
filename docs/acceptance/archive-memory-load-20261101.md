# 当前状态副本生成后的加载标记修复（2026-11-01）

版本2026.11.01.080000，基线为2026.11.01.020000。用户正常退出SolidWorks并确认后，本机部署及部署后核对已完成；完整真实存档由用户手动复测。

## 故障证据

本机电测总装，SolidWorks进程22644。07:23:00开始生成同名提交副本，07:23:31收到三个导入缓存的FileOpenPre通知，07:23:38原生复制成功（errors=0，warnings=0），07:23:43副本校验完成。此后结构预检尚未开始，结构化诊断持续记录“等待SolidWorks当前命令结束后继续存档”。只读查询返回CommandInProgress=false、GetRunningCommandInfo的Active=false；服务心跳正常。

原因是副本保存产生的内部导入加载没有对应FileOpenPost，插件的nativeFileOpenInProgress一直为1。PrepareArchiveScopeCoreAsync的命令保护先读取这个标记，导致一直等待。不是上传慢，也不是副本保存仍未返回。

## 修复范围

相对于基线，运行代码只改PdmAddin.ArchiveMemoryCopies.cs：

- 已有文件加载时不开始新的副本生成。
- 同步副本调用期间抑制后台刷新，记录调用前后的加载批次；成功返回后，核对原生命令、启动完成状态、原路径、用户命令和加载批次。
- 只有核对通过才结束本次副本产生的加载标记。查询期间出现新加载、原生操作未结束或接口异常时保留保护，并用中文明确结束本次提交，不进入无限等待。
- 无加载通知的副本和正常收到结束通知的副本走原有路径。

不改选择范围、权限、源文件只读属性、内容及引用规则，不增加操作项，不解除全局原生加载保护，不主动恢复或修改正在运行的旧版会话。
