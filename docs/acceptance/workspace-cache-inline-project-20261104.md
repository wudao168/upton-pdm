## 原因核对

P700016-6 同时保留旧工作目录、服务器工作目录与图档缓存。列表扫描把同一图档的多个路径全部移除，导致文件实际存在时仍显示“未下载”。

打开拦截则来自服务器工作目录的总装内容未匹配已记录版本。07:48与07:59的旧版日志记录了原生引用替换失败、恢复失败并保留 `.ref-*.bak`；两个备份的哈希均为 `246FF6F888B4725CCCC727747487710959FB4BC1CC269B81C0540AA25EE582BA`，与该总装的既有可信引用投影记录一致。当前异常总装哈希为 `FACC25B50B0DFC64DF9C3E1FC3C44A609F72948B5E6601D044C7EAD70C621E76`。

旧目录中的零件和工程图另有不同内容及版本，不能把所有差异都视为缓存残留。

## 经用户确认的本机恢复

用户明确选择“保留异常副本后恢复缓存”：

- 当前异常总装完整保留在 `E:\Workspace\.uplm\Recovery\reference-repair-20261104\CW004-3.SLDASM`，保留副本哈希匹配原异常文件。
- 以独占文件句柄恢复匹配版本的可信备份，恢复后哈希匹配既有可信记录。
- 旧目录的零件和工程图校验未变，未向服务器写入，未提交或升版。
- 恢复后直接调用当前插件原有 `ValidateWorkspace`，43项清单整体校验返回 `true`。

上述恢复为一次已批准的本机数据修复，没有增加自动丢弃真实本地修改或自动覆盖未知副本的产品规则。

本次保留异常副本、验证历史引用备份后恢复，是 UPLM 特有引用改写残留的修复，不是 PDM 官方的内部恢复实现。后续涉及替换文件内容的冲突处理继续先说明具体影响并确认，不混淆真实修改、旧缓存与技术投影。
