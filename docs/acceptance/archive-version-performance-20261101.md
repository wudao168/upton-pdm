# 引用版本校验提速与超时提示（2026-11-01）

版本2026.11.01.180000已部署到本机。用户确认当前存档结束并保存或备份退出后，完成API及三处插件更新；真实整批存档仍由用户手动复测。

## 故障证据

本机同时作为客户端和服务器。16:30:24开始POST /api/documents/version-verifications，16:30:54在30,016毫秒被客户端取消；下一次23,311毫秒返回200。后续成功请求为21,825–28,547毫秒，间隔出现30秒取消。同期登录和心跳持续返回200。触发原因是版本接口超过通用30秒超时，不是检测到实际断网；旧恢复提示将超时、连接失败和503混为“连接暂时中断”。

调用链每份图档执行HasDocumentAccessAsync → FindDocumentAsync、项目权限、ListProjectFoldersAsync；后者每次初始化整个主项目目录并重算所有目录权限，服务层又再次FindDocumentAsync。批量版本接口因此仍有大量逐文件重复数据库工作。

## 规则与改动边界

依照PDM官方[检入说明](https://help.solidworks.com/2024/english/EnterprisePDM/FileExplorer/r_File_Check_In_Dialog_Box.htm?id=0.3.0.2)，保留逐图档权限、引用及版本核对。官方没有规定UPLM的SQL组织、缓存方式或超时秒数；本次为UPLM内部实现优化。

- 新增仓储批量读取图档身份与可见项目映射。正式图档轻量读取id/project_id/folder_id，暂存图档批量读取原有登记记录；每份图档仍分别判断目录View权限。
- 在同一HTTP请求、同一账号和公司内，每个主项目目录只读取、初始化及计算一次，继续使用原有目录权限解析器；不在不同请求之间缓存权限结果。
- 服务层仍对每个归属项目执行原有项目权限校验，原版本摘要SQL和绑定版本校验不变。无权、缺失、已删除图档不提供版本身份。
- 引用版本接口使用已有长请求连接，并加独立120秒取消期限；其他普通HTTP请求仍为原上限，已有5分钟故障恢复机制及整批提交规则保留。
- 超时提示为“服务器响应超时”，502/503/504为服务暂不可用，连接异常为连接失败；成功重试显示“服务器请求已成功”，不再把慢请求称为断线恢复。最终等待超时也采用请求重试表述。
- 显示当前核对批次及实际完成数量；205份示例显示100/205、200/205、205/205。每批最多100份的范围不变。
