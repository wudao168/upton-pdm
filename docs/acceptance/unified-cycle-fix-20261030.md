## 产品改动

- 新增共享的迭代式含环分组算法，客户端和服务端均使用。不会遇到第一个环就终止分析；保留同文件自引用与真实普通依赖循环保护。
- 客户端为外部依赖补充类型证据是否已核实的状态，候选组含未核实边时显示“引用类型待核对”，不伪称已确认普通循环。
- 存档准备及提交准备两个入口都接入按需补证据：先收集候选分组，只处理其中缺证据的来源实例；优先复用已加载模型，否则沿实际实例层级定位组件，仅解析轻化目标。压缩或无法定位的目标不擅自启用，保留明确的待核对结果。
- 读取原生来源后使用同一个分类函数更新外部依赖。配置不匹配时保留待核对，不自动切换配置。原生上下文记录同时保留配置选项和配置名；悬空状态不再自动改变已识别的关系类型。
- 解析操作有独立的操作计数和刷新抑制。只有该原生调用已经返回、目标模型路径匹配、启动完成、命令空闲且没有后续加载事件时，才清除本次产生的加载标记。原有未保存状态保留。预先存在的加载、活动命令、解析异常、错误模型或后续新加载均不强制清零。
- 引用补齐缓存恢复时，只有原文件内容指纹及配置仍匹配才继承上下文结论；上下文恢复为独立环境记录，不把目标装配成员复制到上下文回指下。
- 原存档范围、权限、工程图更新及原文件内容不因本次分类修复自动改变。提交快照保留原有上下文标记语义，服务端仍拦截普通文件闭环，并一次列出全部含环分组。
