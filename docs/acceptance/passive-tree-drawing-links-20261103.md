# 工作区打开后设计树缺少2D关联

日期：2026-11-03。候选插件：`2026.11.03.201000`。

## 已确认原因

对 P700016-6 执行只读事务查询，仍有 5 份工程图与 24 条模型/工程图关联。工作区列表组装时调用了现有 `ReconcileProjectDrawings`，但打开图档后的轻量设计树刷新和按需展开流程遗漏了该步骤，造成关联已入库、设计树未显示。

旧插件 `2026.11.03.185733` 在新增回归中复现“工作区打开后的轻量设计树补入总装关联工程图”失败。数据未被删除。

## 修复范围

仅修改产品文件 `PdmAddin.PassiveTree.cs`：

- 轻量刷新及按需展开均使用现有项目关联清单补入2D节点。
- 复用关联请求缓存，不按组件重复查询；不增加原生组件读取、解析、保存或磁盘搜索。
- 只根据图档编号匹配关联，并从当前受控清单绑定本地路径、版本编号和模型节点。
- 2D节点不影响子装配的按需展开；重复刷新不重复添加。
- 不改动数据库关联、存档范围、权限规则、历史版本或图纸内容。

## PDM 对照

[SOLIDWORKS PDM Add-in Options](https://help.solidworks.com/2020/english/EnterprisePDM/fileexplorer/solidworks_add-in_options.htm) 明确支持通过 SQL 数据读取优化树显示，并在获取、检出、检入等动作后更新树。UPLM 的“将已关联工程图显示在模型下”是现有自定义展示方式；本次使工作区列表和打开后的设计树使用同一关联来源，不将其表述为 PDM 强制的树层级规则。

## 验证与交付

- 10组针对性检查合计289项通过，其中包含轻量树、工作区按需加载、2D/3D流程、受控打开边界及 H620 来源定位回归。
- 使用真实只读查询结果回放，5份2D及24条关联全部补入，连续刷新三次没有重复节点；未连接 CAD 或向服务器写入数据。
- 178份源码与候选 PDB 校验值匹配，相对已安装18:57版仅上述一个产品文件变化；三个嵌入资源保持一致。
- 发布前发现两处安装插件为18:57版，后台副本为17:30版；分别固定已核实的旧哈希，部署后统一三个目录。
- 发布证据位于 `tmp/passive-drawing-links-20261103/final-verification.json`，包括实际版本、9个原生部署文件、后台心跳、API健康、在线界面及图纸前后校验。

本次没有执行真实图档存档或自动重开总装。最终 SolidWorks 中的显示与操作由用户手动复测，不把数据回放或隔离回归表述为实际业务窗口已验证成功。
