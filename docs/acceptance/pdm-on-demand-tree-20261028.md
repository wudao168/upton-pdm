本次授权：用户于本问题审计与 PDM 对照方案后确认“实施”。真实业务图纸仍由用户手动测试，不启动、关闭或修改真实 CAD 图档；本次构建与自动回归均使用隔离文件、模拟 COM 和模拟 HTTP。

## PDM 对照

- 官方的插件选项支持选择哪些事件自动刷新树、是否重新加载未加载的组件，并提供从数据库读取变量的优化方式。UPLM 本次采用“事件更新轻量状态、按需读取索引、明确操作再核对实际图档”的自定义实现，不宣称这是 PDM 的内部实现。
- 官方检入界面区分只选择父文件与连同引用选择，检入版本保存对应的引用版本。性能优化不移除必要的引用身份、内容、版本、权限与服务器最终校验，不把检查引用等同于上传引用。

## 实现边界

| 场景 | 本次行为 |
| --- | --- |
| 普通本地图纸打开、切换、保存 | 只读取当前图档路径、类型与修改标记，不扫描组件、配置、工程图视图或相关图纸，不查询 PLM 版本。 |
| 受控图档普通编辑 | 保留权限保护、心跳和草稿；事件使本地结构证据失效，已有结构仍可展示。 |
| 查看设计树 | 使用内存缓存或绑定版本的 PLM 索引；尚未读取的装配分支在展开时查询服务器。虚拟组件保持嵌入层级。 |
| 执行存档、属性操作 | 延迟结构必须先通过实际图档读取；索引不能被当作完整的本地存档证据。确认范围后继续实际结构与引用完整性核对。 |
| 已验证压缩子装配 | 同路径、实例、配置、身份和内容满足条件时保留验证结果，避免刷新后丢失结果而重新打开；实际变化仍重新读取。 |
| 引用内容检查 | 保留三个检查时点，每次集中在后台完成文件哈希读取；不同检查点不共享可变文件哈希。 |
| 上传前校验 | 准备副本完成后对每个提交文件执行一次最终服务器预检，随后复核本地内容和保存状态；整批提交仍由服务器确认。 |
| 提交后刷新 | 先使用回执更新节点，后续自动刷新只更新轻量状态，避免立即再扫完整原生树与逐文件历史。 |
| 批量引用版本摘要 | 同一请求中复用项目权限判断；每个图档仍核对文件/文件夹权限。不同请求不缓存权限结论。 |

普通文件初次显示的根节点是“按需读取”状态，不代表空装配。首次进入实际 PLM 操作、手动刷新、图档实际变化或索引不满足完整性要求时，仍可能读取原生结构。这些必要检查不作为冗余检查删除。
