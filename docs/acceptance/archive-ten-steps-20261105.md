# 当前项目图档整批存档的10个显示阶段

适用本机插件2026.11.05.120000的项目图档“提交存档”，不把获取编辑或标准结构入库分支混同为同一流程。阶段名称来自ArchiveStepInfo，实际动作来自PdmAddin及ArchivePreparation。10步是UPLM界面划分，不是PDM官方固定的10个步骤，也不是十段互不重叠的事务。

| 阶段及当前界面名称 | 主要动作 | 作用和目的 |
|---|---|---|
| 1/10 读取文件清单 | 读取可用项目/标准库权限、当前设计树、图模关联及初始归属；提示已知缺失引用。 | 建立可选择的文件清单，此时尚不上传。 |
| 2/10 确认提交范围 | 显示图档与目标项目，确认勾选内容、存档后权限方式、新图档归属等。 | 明确本次操作对象，避免存错项目或误提交。 |
| 3/10 核对引用与配置 | 重新读取当前结构，围绕选中范围核对实际路径、引用、配置、导入/嵌入保存归属、关联工程图和循环引用类型；分析变更，必要时更新工程图内存视图并生成当前状态提交快照。 | 确认提交范围和图档之间的关系可解释、可保存；明确真正需要提交的内容。不是自定义属性必读检查的完成点。 |
| 4/10 核对版本与权限 | 利用版本基准逐份检查文件和引用条件，读取自定义属性（全局及所用配置），记录属性快照和内容指纹。 | 上传前确认能完整取得属性及源内容。此次属性错误在这里被发现；属性本身为空仍合法，未完成读取不能当作成功。 |
| 5/10 预留图档身份 | 批量预留待登记图档的身份，核对归属并准备/验证必要编辑权限与会话。 | 使本批文件及相互引用具有确定的PLM身份。可能产生预留记录或权限操作，但尚未产生正式存档版本。 |
| 6/10 准备上传副本 | 批量读取所需版本记录，核对登记后的引用身份，准备原文件副本或已验证当前状态副本，复用可验证的属性/内容。 | 固定实际要上传的字节、属性和必要关联；不是上传，也不等于强制保存原图。 |
| 7/10 固定快照与最终校验 | 固定本批引用关系、引用版本与提交基准，校验最终整批关系、文件状态及整批请求容量。 | 确认冻结后的提交包一致且满足服务器条件，避免上传后才发现可预知的包内问题。 |
| 8/10 上传文件 | 传输已准备副本到服务器暂存；有可复用存储内容时可省去重复传输，显示文件及字节进度。 | 把文件内容准备到服务器。文件上传完成仍不等于正式存档成功。 |
| 9/10 整批提交 | 发送批次提交请求，服务器最终校验版本、权限及引用，在事务中确认图档版本、属性和引用，按选择处理编辑权限。 | 正式提交本批结果；连接异常时须核对原批次回执，不能直接重复提交。 |
| 10/10 核对结果与刷新状态 | 根据回执同步本地身份/版本/编辑记录和设计树状态，处理可清理的副本及临时读取，汇总成功和提示。 | 使插件和工作区与服务器结果一致。到此之前第9步已正式提交，本地刷新问题不能当成服务器没有存档。 |

属性完整性主要在4/10确认；6/10准备变化后的副本时仍可能补读或复验。属性读取不是到8/10上传时才进行。

3/10、4/10、7/10和9/10均有检查，但对象不同：实际结构与选择范围、逐文件输入、冻结后的整批快照、服务器提交瞬间的最终条件。期间有并发改动或连接变化，后续步骤仍可能失败，不能承诺第7步通过后不会再出错。

当前“核对版本与权限”的标题未覆盖属性读取；真正的预留身份/编辑权限准备主要在5/10。表格按代码说明，不因标题简化而忽略属性。

BOM和通知可以在服务器确认整批后由后台继续生成，10/10完成不保证所有BOM派生任务已经结束。进度分母是当前阶段的处理项：图档、必要辅助文件、引用核对项或批次，不保证始终等于人工勾选数；9/10通常是1个整批提交请求。
