# 存档后本地同步与文档索引优化

版本：2026.10.31.170000。以已部署151001为基线，保留其独立存档窗口、状态代理窗口处理及此前引用性能修复。最终部署证据：`tmp/archive-final-sync-20261031/final-verification.json`。

## 本次依据

OP170批次42d71df6-6096-4705-847c-ff1f53f9c206实际运行151000：332份上传约95秒、服务器提交约95秒；14:00:48至14:55:44完成330份本地缓存，收尾耗时约55分钟。源代码显示每个文件完成时调用编辑日志ReadAll后按DocumentId过滤，当前账号6392条记录会造成约212万条记录读取。

分析完成后发现磁盘已部署151001，PDB171份源码全部匹配。其保存检查已有索引，但未命中会回退逐文件全量枚举，因此对大量未打开文件仍有重复开销。此次没有覆盖或撤销151001的窗口修复。

## 改动

1. EditDraftJournal.ReadDocument按DocumentId读取该图档所有会话XML。FinishLocalEdit保持原有状态转换，不删除历史记录或恢复副本。只核对匹配记录，不读取其他图档内容。本机7511个现有XML文件名均符合当前sessionId-documentId格式。
2. 保存状态核对和只读装配判定共享本轮已打开文档索引。未命中不再重新枚举全部文档；路径先归一化，不能归一化的原生长路径仍保留精确匹配。文档加载事件或已命中对象失效时重建索引。
3. 文件内容校验、身份记录写入和缓存复制在后台执行；COM文档读取及内存状态更新留在CAD线程。完成同步后才返回结果，不提前把“服务器已提交”当成本地同步完成。
4. 缓存优先使用已经上传的固定副本，重新验证其SHA256及长度与服务器最终回执严格一致。无上传副本的路径保留原校验流程；提供的副本损坏或不一致不会静默降级放行。
5. 原始工作文件仍在身份同步前、同步后检查内容；发现提交后的新增修改时保留文件和待提交状态。既有缓存内容不同时不覆盖。新缓存先写临时文件并校验，再原子移动。
6. 缓存冲突和账号变化的提醒不会被后续编辑基准推进清除；本地同步问题不能把已完成的服务器提交误报为整批未提交。
7. 第10步补充编辑记录与实例状态、源文件/身份记录、固定副本缓存、后续修改核对的提示与耗时记录。

未更改服务端业务、提交协议、版本/权限/引用规则、勾选范围、原始文件名。未生成安装包。
