- UPLM 的“提交当前状态副本并保留原文件”、持久提交回执、自动备份及两级项目工作区属于自定义实现。备份与回执不称为 PDM 原生功能。

## 真实原因

P700016-6 的零件及配套工程图已在服务器生成 V3，但当前工作文件仍绑定 V2。零件磁盘内容不同于 V2 原基准，工程图仍匹配已验证的 V2 引用定位副本；两者均可写，原编辑记录已结束。

旧实现把“旧缓存可写”单独作为未核对修改条件；当前状态提交副本成功后又缺少跨进程的源内容提交回执。总装打开前的整套缓存检查因此拦截，报错后没有工作区内的后续操作。

## 修复

- 以实际内容、基准和图档身份识别差异，单纯可写的无变化旧缓存不再误报。
- 提交回执分别记录源磁盘字节及已确认服务器版本，按服务器、公司、登录账号、机器和物理路径隔离；不把仍未改写的源文件标为新版本。
- 回执同时固定原基准版本和指纹。缓存同步后，旧回执不能掩盖用户再次回退为旧字节的修改。活动草稿、后续修改和不同账号/公司不会被回执自动放行。
- 已关闭、可确认的受控缓存可从已校验提交副本同步。打开中的源文件保留，在后续工作区打开时按回执更新。库外源文件不改写。
- 真实差异在“工作区”内列出文件、本地基准和 PLM 版本，可取消、恢复编辑或保留备份并取得最新版；不另开操作窗口，不要求用户到本地文件夹处理。
- 恢复编辑仅在现有最新基准、当前物理路径和权限可核对时启用；不接管其他编辑会话，不新增旧版编辑规则。
- 备份包含差异文件、原绑定/属性及恢复记录、可读取草稿的原字节和实际指纹。取得新版后仅结束已备份路径的旧自动恢复状态，原记录和草稿保留于恢复备份，不再自动覆盖新版。
- 若先续接的修改和其他冲突同时存在，选择 PLM 最新会先将全部差异列明并备份，清除本次保留编辑标记，避免把本地内容混称为 PLM 最新版。
- 校验、备份和文件更新在后台执行，安装前回到 UI 线程一次核对占用，再检查等待期间的字节变化。文件替换保留回滚，并以读共享约束阻止正在写入的文件被强制覆盖。
- 保持既有工作目录，仅获取需要更新的文件；恢复备份不列入可自动清理的已验证缓存目录。
