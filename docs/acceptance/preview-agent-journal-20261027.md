# PC-07 日志文件启动弹窗修复（1.2.3）

用户在更新 1.2.2 后反馈 SolidWorks“无法生成日志文件，目前恢复将不可使用”弹窗。
PC-07 健康接口确认代理和转换程序均为 1.2.2；实际上传日志显示 18:28:24 自动回收旧 PID 1132，随后新 PID 25964 在两分钟后连接超时，之后为同批下一个文件再次启动。
这说明旧进程已被回收，而新的启动仍受到阻塞，不能把本次弹窗继续解释为人工打开 SolidWorks。

## 原因和改动

1.2.2 显式启动专用进程时，没有像仓库原生存档会话一样隔离 SolidWorks 日志目录，工作目录也指向安装目录。
默认日志目录被占用、不可写或旧日志损坏时，仍会出现这个启动弹窗。旧版没有记录实际日志路径，不能单靠旧日志断言 PC-07 默认目录的具体故障类型。
该错误的路径、权限和损坏原因可参见 [SolidWorks 官方说明](https://blogs.solidworks.com/products/solidworks/six-solidworks-solutions-startup/)。

1.2.3 在当前 Windows 用户的 LocalAppData 下为每次启动创建独立日志目录，并实际检查写入权限。
只在启动期间临时设置相应 SolidWorks 版本的日志目录，启动完成后恢复原值及注册表类型；进程继续写入其独立日志。
恢复记录先落盘，异常退出后下次启动会恢复未完成的设置；并发修改的用户设置不会被覆盖。启动互斥与原生存档组件使用同一名称。
独立工作目录也移出 Program Files。诊断日志记录原目录、专用目录和写入校验结果。

启动失败只尝试一次，同批剩余文件直接记录失败，避免 32 个文件逐个等待两分钟。
安装器在专用机模式下允许恢复已经卡住超过一分钟、尚未连接 SolidWorks 的 1.2.2 启动请求，再升级程序；正常转换、刚开始的启动和普通模式仍不强行中断。

## 验证

- 13 项日志目录检查：原值缺失、字符串及可展开字符串类型、不可用或被占用的默认路径、并发偏好保留、无效类型拒绝、真实工作进程被终止后的设置恢复。
- 真实 SolidWorks 4 项：锁住默认 swxJRNL.swj 后成功启动，在独立目录实际生成 swj，运行中已恢复原设置，原日志内容不变。
- 启动失败回归：三个文件只尝试一次初始化，后两项停止重复启动。
- 1.2.3 最终安装载荷重新转出两个项目下 -02、-05、-07 共六张原真实工程图；16 个原存档文件哈希不变。
- 前台代理 26 项、升级脚本 17 项及完整安装器 28 项通过；升级脚本已在 Windows PowerShell 5.1 验证，覆盖恢复卡住的启动、拒绝中断正常转换以及配置回退。
- 服务器已收到 PC-07 的自动上传日志，日志接口已随统一发布上线。本次没有再替换 API 或网页构建。
