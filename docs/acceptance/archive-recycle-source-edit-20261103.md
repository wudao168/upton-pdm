## 本次修复

1. 原路径成功存档后继续编辑，设计树重新扫描可能丢失内存中的图档编号。现在提交边界再次恢复可信成功回执中的项目、路径和图档身份，继续使用原图档登记及正确的工作版本基线。
2. 已提交的内存副本不能被较早磁盘回执降回旧基线；只恢复仍打开、同用户及服务器范围、同项目、路径和校验匹配的可信关联。历史预览和受控工作区不采用库外源文件恢复逻辑。
3. 同名同内容的辅助图档沿用既有登记，写过程记录，不再弹出只有确认或取消的说明对话框。真正的新文件、异内容冲突、权限和版本校验仍保留。
4. 初始选择阶段取消明确显示“已取消、尚未上传或升版”；已经进入提交阶段的失败或结果不确定提示保持原有语义。
5. 相同父级下同一图档编号的重复工程图展示去重；同名但不同编号的记录以及真实装配实例不按名称合并。

## 管理员按存档批次回收 / 恢复

入口：项目 → 文件 → 受控图档目录 → **按存档批次回收 / 恢复**。

- 先选择批次、预览回收和保留清单，填写原因并勾选核对后执行。
- 仅回收该批次新建且尚无后续版本的可回收图档。已升版、已发布、审核中、正在编辑、后续任务未完成或被范围外图档引用等情况会显示具体原因。
- 范围内的装配、零件和工程图成套处理；预览后发生版本、检出或范围变化时，整批拒绝，不部分回收。
- 采用软删除并保存历史；30 天内可成套恢复，不提供永久销毁。恢复同样在事务中处理冲突。
- 保留其他项目图档、原有/人工物料及人工维护数量；只调整所回收图档对应的自动 BOM。原电脑和共享目录的原文件不改动。
- 成套回收成员不能绕过成套恢复入口逐份恢复。

## PDM 规则与保留差异

- 官方 [Check in Dialog Box](https://help.solidworks.com/2025/english/EnterprisePDM/itemexplorer/r_Check_In.htm) 区分本次检入选择、继续检出以及是否产生版本。UPLM 本次修复保持原图档身份和历史，未因同名或重新扫描而新建业务图档。
- 官方 [Folder Properties](https://help.solidworks.com/2025/english/EnterprisePDM/FileExplorer/r_Folder_Properties.htm) 将删除、恢复和永久销毁区分，并受权限及工作流状态约束。UPLM 采用管理员预览后软删除和恢复，不开放永久销毁。
- “按存档批次成套事务处理”“30 天恢复期”是用户批准的 UPLM 自定义策略，不表述为 PDM 原生规则。原图档历史恢复仍采用新建工作版本、保留原有历史的既有机制。
