# SolidWorks 交互流程与 SOLIDWORKS PDM 对照审查（2026-11-16）

## 结论及范围

本轮问题不是特定图号的问题。已确认：获取前的结构检查递归到了子装配，但历史引用证明只准备在所选装配层；另一个入口又从子装配文档的活动配置重新遍历，混淆了文档和装配实例。设计树缓存还存在路径键与配置键不一致的问题。上述缺陷分别影响获取、打开、切换后的显示，不能靠放宽单个错误提示解决。

本轮审查覆盖普通交互入口：客户端/工作区打开最新、指定历史版本、设计树单件打开、根/子装配/零件/工程图获取、原生保存、存档选择与提交、提交后同步、放弃及恢复、再次获取、窗口/配置切换、重建、后台刷新。索引了插件中打开、关闭、保存、激活、切换配置、解析、重建及只读状态等主要可变更 API 调用，追踪其普通交互、显式操作、隔离副本三个调用范围。

这不是所有 SolidWorks 功能及任意 CAD 文件均已实机验收的声明。参数设计、外部应用、宏、特殊导入格式、所有 SolidWorks 版本组合仍需对应真实样本。普通工作流不应因为这些专用能力存在就触发它们。

## 官方规则与 UPLM 选择

以下依据是官方公开说明；其后的实现建议是 UPLM 的设计判断，不声称 PDM 内部采用相同代码或恢复机制。

1. **编辑权与取回引用分开**：PDM 可仅检出选中文件，也可以通过配置带入引用；取回最新引用不等于给全部引用授予编辑权。[引用对话框设置](https://help.solidworks.com/2025/english/EnterprisePDM/Admin/IDD_PAGE_LOCK_FILES.htm?id=2.27.16.17)
2. **最新引用是一项策略**：PDM 可只取回缺失缓存、预选过期引用，或强制使用最新引用。UPLM 根据用户既有要求，“打开最新”采用最新模型引用，指定历史版本保持历史组合；不因此强制父装配升版。[检出时的引用获取策略](https://help.solidworks.com/2025/english/EnterprisePDM/admin/t_controlling_handling_of_references_for_checkout_state_change.htm)
3. **保存与检入分开**：检入之前的保存只在本地；检入界面支持选中文件、保留检出及检入后继续打开/关闭。不能把关闭整个装配作为正常再次获取的前提。[检入对话框](https://help.solidworks.com/2025/english/EnterprisePDM/FileExplorer/r_File_Check_In_Dialog_Box.htm?id=0.3.0.2)
4. **警告与硬错误分开**：缺件、库外引用、未重建等可由管理员配置是否阻断；真实循环等错误仍阻止提交。不能将每个历史路径或未重建状态都无条件扩大成获取失败。[警告策略](https://help.solidworks.com/2025/english/EnterprisePDM/admin/IDD_USER_GROUP_WARNING.htm)
5. **版本与发布修订分开**：UPLM 用户可见图档版本 V1/V2…，发布 A/B/C…；内部旧 W 标记不能决定是否是同一文件或向用户混用显示。[版本与修订](https://help.solidworks.com/2025/english/EnterprisePDM/fileexplorer/c_Versions_and_Revisions.htm)
6. **放弃是显式丢弃操作**：只处理确认的文件。UPLM 的草稿日志、失败恢复记录和服务器租约属于自定义机制，不能表述为 PDM 原生行为。[撤销检出](https://help.solidworks.com/2025/english/EnterprisePDM/fileexplorer/r_undo_check_out_dialog_box.htm)

API 事实也影响判定：`GetComponents(false)` 已包含根装配当前配置的所有层级，不能再把每个子装配文档当作新根遍历。层级比较使用实际 `IComponent2.GetChildren()` 和引用配置；文件级来源核对可在根的完整实例清单上一次完成。[GetComponents](https://help.solidworks.com/2024/english/api/sldworksapi/solidworks.interop.sldworks~solidworks.interop.sldworks.iassemblydoc~getcomponents.html)

`GetSaveFlag` 是保存标记，并不是 PLM 内容差异或编辑权。官方还说明旧版本创建的文档也可能带此标记；不能仅凭它断定用户新增了零件，亦不能仅凭只读就清除它。[GetSaveFlag](https://help.solidworks.com/2025/english/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IModelDoc2~GetSaveFlag.html)

## 前后必须一致的判定对象

| 对象 | 唯一含义 | 不能替代它的状态 |
| --- | --- | --- |
| 图档身份 | 公司/项目、DocumentId、实际路径及文件类型 | 显示名称、同名文件、树上选中项 |
| 工作基准 | VersionId、服务器哈希、本机校验记录，必要时包含已提交回执 | 单独的 V/W 显示文本、修改时间 |
| 磁盘内容 | 当前文件真实哈希及长度 | 内存保存标记、服务器最新版本标签 |
| 内存状态 | 当前 COM 文档、实际路径、更新戳、保存状态和已提交内存回执 | 已保存磁盘内容、其他窗口的同名对象 |
| 实例结构 | 父实例、引用配置、组件数量、抑制/轻化/虚拟状态 | 子文档独立窗口的活动配置、按文件名去重的集合 |
| 编辑会话 | 服务器授权、账号/公司、SessionId、租约和本次获取记录 | 文件可写属性、界面颜色、用户显示姓名 |
| 操作范围 | 本次要编辑、检查引用、替换、上传的各自文件集合 | 整个会话所有打开文件或整个项目 |

共同服务已包括 `WorkingReuseBindingMatches`、`WorkingReuseDraftMatches`、`ControlledReferenceMaterializer`、`VersionMatchesLocalFile`、`ArchiveMemoryCopy`、`EnsureCheckedOutDocumentEditableAsync`。本轮继续复用这些入口，而不是增加按图号、项目或层级特殊放行。

| 历史/发布版本 | 独立只读上下文，允许查看旧组合；不是直接编辑旧快照 | 保留，受控缓存/历史范围回归覆盖 |

| 零件获取 | 未打开的已验证零件不需要先重开总装 | 保留；无关工程图及上级装配不得成为该零件的额外获取前提 |
| 工程图获取 | 工程图按自身基准处理；模型/工程图共用草稿与可写确认 | 保留；不为工程图获取去保存或切换上层装配 |
| 历史抑制缺件 | 已存档的原地址缺失、实例未加载且仍抑制，与新增缺件不同 | 已修复各层证明范围；原地址必须由原版本文件证明，真实新增或已解析缺件仍拒绝 |
| 轻化受控引用 | 未加载组件可能暴露旧保存地址，而不是当前实际来源 | 复用原生状态+原版本地址+受控文件身份/字节共同核对；不能只凭同名匹配 |
| 只读转编辑 | 文件属性与原生 `SetReadOnlyState` 分开验证；短暂失败后异步让出 UI，再核对服务器租约重试 | 保留；不会用强制重开/丢弃修改来“修好”原生锁 |
| 未获取时编辑 | 原生只读与保存权限约束；既有未保存状态仍要保护 | 不把只读脏标记直接当新增设计，也不清除真实修改。受控新增引用的恢复仍需要身份、版本、配置证据 |
| Ctrl+S/保存 | `SaveManagedDocumentScope` 仅保存已取得权限的范围，工程图不级联保存模型 | 保留；同一保存函数省略 `SaveReferenced`，避免逐子件另存。另存为/保存全部仍有原生不同语义 |
| 存档入口与勾选 | `EnsureArchiveEntryTree` 以活动窗口为入口；`AnalyzeArchiveNode` 共同判定版本/内容；配套变更带入选择 | 保留；不能以树元数据替代当前活动文档，未修改 3D 不因仅改 2D 强制升版 |
| 2D/3D 关联 | 按实际工程图模型关系，部分流程自动取得配套工程图权限 | UPLM 已有配套策略，不是 PDM 所有安装的默认行为；保留此前授权，辅助失败以明细提示，不撤销已成功的主体获取 |
| 存档副本 | 内存快照、已保存文件、工程图保存收尾分别有证据；普通存档不整批重开全部图档 | 保留自定义机制；提交前冻结并验证字节，不能显示成功后才发现原文未上传 |
| 存档后再次获取 | 服务器回执、磁盘身份、内存回执、工作清单需逐项衔接 | 同轮覆盖根装配、子件和工程图；本轮递归引用证明兼容已提交根的同步前/后基准 |
| 放弃与恢复 | 服务器释放和本机还原可能部分成功，日志标记恢复未完成 | 保留可重试恢复和原文件；未改动范围不保存/重开，不把另一图档的恢复记录扩大成全局失败 |
| 窗口/重建切换 | 原生事件延迟刷新，后台不执行整树解析 | 已修复零件缓存配置键失效遗漏；真实结构事件仍要求新扫描，纯权限更新复用树 |
| 性能 | 被动显示只读元数据；显式操作才完整校验；原生 COM 留在 CAD 线程 | 历史原文每个所属版本只读取一次；去掉子树重复扫描；保存检查保持线性索引，不每个文件重新枚举全部窗口 |
| 权限/网络中断 | 服务端授权为准，本机租约/恢复日志提供连续性 | 没有新增业务权限或扩大数据范围；验证拒绝、异项目、版本竞态；不按固定角色放行 |
| 缺件/未重建提示 | `ArchiveMissingReferencePolicy`、`ArchiveWarningGate` 根据当前管理策略处理 | 不将可配置警告统一改成硬错误；当前文件不可读、上传副本变更、身份冲突仍阻止 |

## 本轮修复的实现边界

- `PdmAddin.InsertedWorkingParts.cs`：历史引用证明按实际所属文件、版本、实例配置、路径、数量及加载状态建立；证明本身不授予任何子件编辑权。
- `PdmAddin.WorkingCopyReuse.cs`：选中根/选中子模型共用递归校验。每次异步读取后和服务器获取后复查来源字节与实例证据。新增引用、异项目、错误配置、重复实例、检查期间变化均有拒绝回归。
- `PdmAddin.ControlledReferences.cs`：打开/恢复共用的加载来源检查不再从每个子文档重新展开，避免读取无关活动配置；不同路径的实际加载文件仍拒绝。
- `PdmAddin.cs`：结构失效按文件路径清掉该文件全部配置的缓存。纯权限刷新继续复用未失效缓存，不为了此修复恢复后台全量扫描。

没有改动用户 CAD 原文、强制清除保存标记、扩大检出范围、解除智能/上下文关联或改变管理策略。本轮没有 API/数据库变更，也不重新授权任何角色。

## 仍需明确区分的差异与风险

1. **内存副本存档不同于直接保存原文。** 这是 UPLM 为保护原文件而采用的机制。服务器成功、本地已同步、窗口已同步必须分开记录；窗口之后出现真实修改应保留。不能承诺任何存档后关闭都绝无保存提示，也不能自动点击“不保存”。
2. **PDM 的引用警告可配置，不代表全部可忽略。** UPLM 对实际加载异路径、真实内容变化、失效租约保留更严格的防覆盖检查。建议沿用已有管理策略，只消除证据不一致造成的误报，不增加“忽略所有错误”。
3. **配套工程图自动获取是 UPLM 的既有产品选择。** 若以后要改为完全逐文件选择，应作为操作方式变化确认，而不是在本轮修复中悄悄取消。
4. **工程图多图页、多模型与多配置需要独立样本。** 关联索引已按图页/视图和模型身份检查；此次模拟覆盖图页关联和多实例配置，不等同所有剖视/详图/替代位置/SpeedPak 均已真实验证。
5. **已有隔离转换工具与普通存档不同。** `ArchiveNativeCopyWorkspace` 等专用工具包含解析、保存、切配置；本轮追踪普通存档只使用其明确的校验入口，未把专用转换重新引入普通获取或后台刷新。未使用的历史工具不在此轮删除。
6. **树显示不是获取决策的最终事实。** 数据库元数据可能已更新而本地原生窗口尚未同步。显式操作按实际源文件/实例核对；UI 不应仅凭服务器 V2 标签宣称内存也已是 V2。

## 2026-11-16 后续：总装存档后获取零件被上级版本阻止

用户已确认 `104655` 对 P700017-14 的主装配及子装配获取、存档正常，但随后对 `70005255.M01.03.01-02.SLDPRT` 获取失败。该反馈不等于整个获取链路已验收。当前修复候选为 `2026.11.16.135257`，证据目录 `tmp/selected-scope-20261116`。

### 确认的原因

运行日志 PID 9252 记录 13:01:59 四份图档存档成功；13:02:52 获取单个零件；13:02:55 的校验范围却为 `selected=1 dependencyFiles=522 workspaceFiles=522`，13:03:02 被“总装基准版本已变化”阻止，尚未发出该零件的检出请求。

通过只读事务查询该零件的准确存档版本 `9146afae-900f-4866-8a97-7e3f76d816a9`，确认快照包含两条指向 `70005255.M01.SLDASM` 的环境引用：`IsContextReference=true`、`Role=ExternalFileDependency`、`Kind=Assembly`、无子节点，且未标记类型待核对。版本原始快照保存在 `part-versions.json`，凭据未输出或保存到诊断文件。

1. 服务端下载清单会展开装配环境所属的文件。旧获取逻辑把下载清单直接当成零件的实际设计依赖范围，因此整套 522 文件进入校验。
2. 即使投影为单件范围，工作清单仍保留上级根版本字段，旧的清单比较和错误解释又无条件比较该字段。因此上级正常存档升版也可能被当成本零件冲突。
3. “打开并获取”预检查与“已经打开后获取”的环境分类入口不同，单修其中之一会留下另一入口的误拦。

### 共用规则及 PDM 对照

[PDM 官方 Reference Dialog 设置](https://help.solidworks.com/2025/english/EnterprisePDM/Admin/IDD_PAGE_LOCK_FILES.htm?id=2.27.16.17) 分别配置检出选择、引用下载和自动检出引用；静默检出可以仅处理选择的文件。由此采用“操作范围与下载清单分开”的实现建议。官方页面没有规定 UPLM 的工作清单或环境标记格式，下列证据规则属于 UPLM 实现，不称为 PDM 原生算法。

- `ReadModelAcquisitionFileIdsAsync` 按精确存档快照遍历实际依赖，仅排除有明确证据的装配环境及仅由这些环境带入的下载成员。同一文件同时是实际驱动或组件时，实际依赖优先。未知引用、证据缺失或畸形环境记录不按环境放行。
