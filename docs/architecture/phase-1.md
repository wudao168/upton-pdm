# 一期架构与边界

## 交付边界

一期包含SolidWorks插件、Windows客户端、PLM API、MySQL 8.4数据模型和项目级文件存储。网页项目管理、车间扫码、装配调试追踪、质量闭环、U9自动同步和历史全量迁移不在一期范围内。

## 关键约束

- 工作版本使用`W1/W2/...`；首次审批发布为`A`。已发布`A`后发生变更时依次进入`A-W1/A-W2/...`，再次审批发布为`B`，以后类推。
- 业务界面统一使用图纸字母版次：未发布的工作存档显示“A-D”，A 版之后的修改显示“B-D”，D 表示 Draft（草稿）；正式发布后去掉 -D。中文悬浮提示区分设计中、修订中和当前生产版次；存档号保留在历史与详情中。已发布 BOM 按本包冻结版本绑定显示正式版次，当前 BOM 仅在源存档确有对应正式版本时显示该版次，不能直接将所有 W1 改为 A。缺少绑定的历史发布数据标记“历史版次待核对”。整张清单的 V 系列明确标为“BOM 发布版本”。导出 Excel 的存档号放在隐藏列，重新导入仍保留原值。
- 所有历史版本永久不可修改、覆盖或删除。恢复历史内容时按当前最新版本推进新的工作号，例如当前为`W3`时恢复`W1`生成`W4`；恢复正式`A`的内容也只能生成新的`A-Wn`。
- 文件属性、引用树、机械BOM和电气件BOM随每个版本保存为不可变快照，版本对比不依赖当前图档状态。
- 发布包审批固定为工艺审核和批准两级；审批完成后原子投放生产目录。
- 签入只保存 SolidWorks 源文件和工作版本，不生成预览副本。最终审批通过后，API 所在服务器调用独立 SolidWorks 转换进程：零件/装配生成与批准源版本绑定的 STP/STEP，工程图生成 PDF，再生成不可变发布包；个人电脑和 SolidWorks 插件不参与转换。
- 发布包只包含服务器生成的 STEP/PDF、机械/电气件BOM XLSX、清单、审批记录和 SHA-256 校验文件，不包含 SolidWorks 源文件；DWG 不再生成、校验或写入新发布包。
- MySQL只保存业务数据、文件路径、大小和哈希，不保存CAD/PDF二进制。
- 个人列显示和列宽通过 `/api/me/table-preferences` 按认证账号及当前公司保存到 MySQL，采购跟踪、各类 BOM、生产图纸共用同一机制。旧本机设置首次迁移，本地仅作缓存；登录及重新进入页面时恢复账号设置，保存失败不误报已同步账号。数据库迁移为 `187_user_table_preferences.sql`。
- 标准结构首次存档时，在“未分类”下按首次完整编号（如 `UPST-1-0001-V01`）自动建立型号分类目录，并与完整图档及 BOM 的归属一同提交。重复请求不重复建目录，升版保留目录和历史版本，人工调整归属后沿用人工分类。“未分类”本身仍固定，但允许维护其子分类；分类变化不改变存档文件路径。
- 标准结构按整套根图档管理启用、停用及回收站状态，子装配、零件、工程图和各版本 BOM 一同保留，不物理删除存档文件。停用分类（含上级分类）或结构后禁止新增项目引用，已有项目 BOM 不回写；恢复分类不改变结构自身的停用状态。已有引用或待核对引用的结构不能移入回收站。新引用先在目录 JSON 中保存占用再写项目 BOM，失败时保留待核对记录；历史引用另查专用审计，不受普通审计的条数及操作人限制。目录 JSON 兼容旧数据，无需新增数据库表。
- 项目分别绑定受控图档库与生产发包目录；存储不可用时禁止签入或发包。
- 图档引用树保留实际装配实例，包含总装、子装、零件及关联工程图；不复制FeatureManager草图、特征和配合树。

## 客户端设计系统

- 基础背景`#f4f7fb`、白色内容面板、边框`#dbe3ef`、圆角8px。
- 深蓝侧栏和标题栏，主操作蓝色，签入/通过使用绿色，异常使用橙色或红色。
- 主工作区由项目图档树、2D/3D/BOM视图和审批/发布状态组成。
- 控件字体使用Microsoft YaHei UI与Segoe UI，密度接近现有CRM。
