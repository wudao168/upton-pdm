# SolidWorks 受控工作区、缓存与外部副本规则

## 核心结论

- PLM 中的图档记录和不可变版本是唯一正式来源；本机文件只是工作副本或只读缓存。
- 每次打开不必重新下载。客户端先取得 PLM 打开清单，校验本地文件的长度和 SHA-256；完全一致时直接复用缓存。
- 只有配置的 PLM 工作区内、且存在本机绑定凭据的路径，才能自动恢复图档和项目身份。
- 下载目录、桌面、Pack and Go 目录等工作区外路径，即使保留旧图档编号，也只显示为“工作区外的 PLM 来源副本”，不能静默恢复项目归属。
- 工程师日常在 SolidWorks 任务窗格或 Windows 客户端操作，不需要进入真实缓存目录。

## 与 SOLIDWORKS PDM 的规则对齐

| 规则 | SOLIDWORKS PDM 常见做法 | UPLM 实施规则 |
| --- | --- | --- |
| 本地入口 | Vault View 是受控本地视图 | `View/<项目号>` 是项目级受控工作区 |
| 获取文件 | 本地已有正确缓存版本时复用 | 打开清单 + 长度/SHA-256 校验，一致则复用 |
| 只读/编辑 | 签入文件只读；检出后可写 | 默认只读；“编辑打开”成功取得权限后仅目标图档可写 |
| 历史版本 | 独立只读缓存 | `.uplm/Snapshots` 内按项目、根图档、版本隔离 |
| 复制文件 | Copy Tree/复制结果是新的独立实例 | 工作区外副本不自动继承项目身份，重新纳入时集中确认 |
| 离线 | 显式切换离线模式 | 当前版本不提供离线编辑；网络不可用时不得新建编辑权限 |

主要差异是：UPLM 不把 Windows 资源管理器中的真实文件夹作为业务入口。客户端采用相近的导航树、地址栏、命令栏和右键菜单，但操作由 PLM API 和 SolidWorks 插件执行，以避免移动、改名和复制缓存造成关联错误。

## 目录与信任边界

```text
<工作区根目录>/
├─ View/
│  └─ <项目号>/                 # 工程师当前项目工作视图
└─ .uplm/
   ├─ Snapshots/
   │  └─ <项目号>/<根图档>/<Latest|ReadOnly>/<版本>/
   ├─ Staging/                  # 下载校验的临时区
   └─ Recovery/                 # 失败回滚或恢复所需文件
```

- `View/<项目号>` 是一个项目一个可见工作目录；不同根装配不会再创建互相割裂的 Working 目录。
- 更新某套装配时只合并打开清单内的文件，不删除同项目中与本次装配无关的文件。
- 清单内可写且内容变化的文件视为可能未提交修改，刷新必须停止；旧的只读缓存可以安全刷新。
- 清单相对路径必须仍位于目标目录内，包含路径穿越的清单直接拒绝。
- `.uplm` 为系统区，不在日常界面中暴露。缓存清理只能清理未打开、未检出、可重新下载的只读快照；`View`、可写文件和恢复文件不能自动清理。

## 日常操作

### Windows 客户端

项目的“图档”页就是工作区管理入口，采用资源管理器式布局：

1. 左侧导航窗格选择装配、零件或工程图。
2. 顶部地址栏只显示 `UPLM > 项目号 > 工作区 > 文件名`，不显示物理缓存路径。
3. “只读打开”校验并复用本地正确版本；“编辑打开”先取得独占编辑权限，再切换文件为可写。
4. 右键可打开最新受控版、编辑打开或打开最新发布版。
5. 属性、预览、版本和引用关系仍在客户端查看。

### SolidWorks 任务窗格

- “工作区”页选择项目和图档，可直接“只读打开”或“编辑打开”。
- 已打开文件明确显示来源：工作区受控文件、工作区本地未入库文件、普通本地未受控文件或工作区外 PLM 来源副本。
- 工作区外副本不会自动切换当前项目；需要提交或恢复旧关联时仍执行权限、项目和同名内容校验。

### 资源管理器

资源管理器只用于管理员诊断、备份或排障。工程师不应从中改名、移动、覆盖、复制或删除工作区内部文件，也不应把路径书签当作日常入口。

## 本地关联与副本

- 本机关联凭据保存在 `%LOCALAPPDATA%\UPTON PDM\document-bindings`，包含规范化路径、机器、项目和图档编号；它不是服务端权限凭证。
- 普通复制或 Pack and Go 不携带目标路径的绑定凭据。随 CAD 文件复制的 `UptonPdm.DocumentId` 数据流只作为来源线索。
- 不通过文件名或内容相同自动恢复关联。目标项目中同名且内容相同的文件，需要一次集中确认；同名不同内容必须更名、选择其他项目或从受控工作区打开。
- 新装配仍引用打包根目录之外的普通本地文件时阻止提交并列出路径；目标项目中已经验证的受控引用除外。

## 旧本地文件迁移

- 升级时不移动、不删除现有下载目录和 CAD 文件，也不清除其中的属性或只读标记。
- 旧路径绑定继续保留为“来源凭据”，但工作区外文件不再自动获得受控身份。
- 工程师下一次从客户端或 SolidWorks“工作区”页打开时，系统把正确版本准备到新的项目工作区；校验通过后再使用。
- 若旧外部文件有尚未提交的修改，先备份或通过明确的纳入/恢复流程处理，不能用下载的新版本覆盖。

## 验证

`tools/Pdm.BatchReferenceAcceptance` 使用隔离文件、替代绑定目录和模拟 HTTP 验证：外部副本不受信任、项目级工作区合并不删除无关文件、可写修改阻止覆盖、只读缓存可刷新、清单路径不能越界，以及增量提交和失败停止。测试不启动 SolidWorks COM，也不上传业务文件。

仍需在部署环境执行原生验收：客户端只读/编辑打开、SolidWorks 关闭重开、装配引用解析、提交存档、旧外部副本提示，以及 eDrawings/SolidWorks 实际视觉与文件锁行为。
